# Secrets And .env

`.env` at the repository root holds every secret the platform uses. It is excluded from
Git, generated by `scarline setup`, and set to mode `600` on Linux and macOS. `scarline
doctor` fails if the permissions are looser.

Nothing else stores secrets: not `config.yml`, not the database, not the UI. The
Admin Panel's System Settings screen says so explicitly and shows no secret values.

## The Seven Secrets

| Key | Minimum | Protects |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | 1 char | PostgreSQL, for CoreAPI and the container itself |
| `RABBITMQ_DEFAULT_PASS` | 1 char | RabbitMQ, for CoreAPI, Sim-Bridge, and the IO Client |
| `JWT_ACCESS_SECRET` | 32 chars | Signs access tokens, WebSocket tickets, and overlay tokens |
| `REFRESH_TOKEN_PEPPER` | 32 chars | Peppers stored refresh-token hashes |
| `BOOTSTRAP_ADMIN_PASSWORD` | 1–128 chars | The one-time first administrator credential |
| `OVERLAY_CONTROL_SECRET` | 32 chars | Authenticates the desktop overlay host to `POST /api/v1/overlay/token` |
| `SIM_BRIDGE_ADAPTER_SECRET` | 32 chars | Authenticates simulator adapters to the Sim-Bridge `/adapter` socket |

Which service receives which secret is narrowed per service. CoreAPI gets six of them;
Sim-Bridge gets only `RABBITMQ_DEFAULT_PASS` and `SIM_BRIDGE_ADAPTER_SECRET`; a
simulator adapter gets only `SIM_BRIDGE_ADAPTER_SECRET`.

## How Generation Works

`scarline setup`:

1. Parses the existing `.env`, if any. Unknown keys are an error.
2. For each missing key, generates 32 random bytes encoded as base64url — **except**
   `BOOTSTRAP_ADMIN_PASSWORD`, which is copied from `.env.example`.
3. Appends only the missing keys, grouped under their comment headings. Existing values
   are never rewritten and never printed.
4. Validates the merged result and applies mode `600`.

Deleting a line and re-running `setup` regenerates just that secret.

::: danger BOOTSTRAP_ADMIN_PASSWORD is a known default
It is copied verbatim from `.env.example`, where it is `scarline`. It is a convenience
for local first runs, not a credential. Set a real value in `.env` before the first
`scarline start` on any machine reachable by anyone else.

CoreAPI creates the first administrator with `password_reset_required`, so the first
sign-in cannot reach any screen except `/change-password`. The replacement must be at
least 12 characters, and setting it revokes the refresh cookie.
:::

## How Secrets Reach Services

`compose.yml` passes each secret with the `${VAR:?message}` form, so Compose refuses to
start a service whose required secret is absent and prints which one is missing.

Host processes started by the CLI receive their secrets through the spawned process
environment: the desktop overlay gets `OVERLAY_CONTROL_SECRET`, and the host-mode IO
Client gets `RABBITMQ_DEFAULT_PASS`.

Compose failure output is scrubbed of known secret values before the CLI prints it, so
error text is safe to share.

## Rotating A Secret

1. `scarline stop`
2. Edit or delete the line in `.env`; re-run `scarline setup` to regenerate a deleted one.
3. `scarline start`

Consequences per secret:

| Secret | Effect of rotation |
| --- | --- |
| `JWT_ACCESS_SECRET` | All access tokens, WebSocket tickets, and overlay tokens become invalid; everyone signs in again |
| `REFRESH_TOKEN_PEPPER` | Every stored refresh token stops verifying; everyone signs in again |
| `OVERLAY_CONTROL_SECRET` | The desktop overlay must restart to obtain a new control token |
| `SIM_BRIDGE_ADAPTER_SECRET` | Adapters must restart to re-register |
| `POSTGRES_PASSWORD` | The existing PostgreSQL volume still holds the **old** password; rotating it means changing the role in the database or discarding `.runtime/postgres` |
| `RABBITMQ_DEFAULT_PASS` | Same caveat for the RabbitMQ volume under `.runtime/rabbitmq` |
| `BOOTSTRAP_ADMIN_PASSWORD` | No effect once any user exists — the bootstrap path only runs on an empty `users` table |
